# DeepSeek与GPT娘帧率复核

2026-11-02。本轮只读检查实际文件、运行进程和有限呈帧计数；没有重启、安装、改帧率或操作鼠标。六条Gemini新素材仍未安装。

## 已确认

1. 当前DeepSeek安装目录106个WebM的视频流信息全部为24fps。另解码待机呼吸休闲、东张西望、点击回应-开心跃动各120帧，PTS覆盖0至4.958秒，帧间隔41～42ms，约24fps。不是只根据扩展名、注释或刷新定时器推断。
2. 当前GPT娘实际安装清单43个状态全部标为30fps，六条新原片也均为30fps。当前运行实例为安装目录widget.ps1的PowerShell宿主，仍是WPF，不是已撤回的Electron龙娘。
3. 当前DeepSeek已安装sprite.js与维护源码字节一致，使用双video播放及requestVideoFrameCallback等待目标画面就绪。未发现将原片动作插帧成60fps的处理。窗口移动和缩放等独立使用requestAnimationFrame，不能用这些回调频率当视频帧率。
4. 当前WPF动作播放器定时检查间隔为1000/60毫秒，但普通动作按素材fps和媒体时间选帧，只在帧索引变化时提交新图像；因此该定时器不能证明人物动作每秒60张新画面。拖动起飞/落地另有加速路径，不可泛称所有动作始终原速30fps。
5. 当前原生窗口运动另有DwmFlush后台时钟，属于交互架构优化。旧PowerShell消息回调负载、窗口更新频率与人物动画素材帧率是不同指标；不能因素材30fps就否认交互优化价值。

只读presence中的时间、PID、clip、presentedFrames等有限字段约20秒。首末有效心跳跨度18.720秒，呈帧提交计数增加397，平均约21.21次/秒；片段涉及frontidle、draglanding、thinking，不是同一稳定动作的严格基准，不能把平均值认定为所有场景的固定FPS。
