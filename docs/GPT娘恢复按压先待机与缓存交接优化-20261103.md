# GPT 娘恢复按压先待机与缓存交接优化

当前正式版为 **0.8.14-electron**，基线为 0.8.13-electron。用户明确要求保留“按压先回待机”，同时修好重影；上一版按压保留原动作的交互策略已撤销。入口仍为原 GPT 娘启动入口。

## 当前交互

其他动作中途按下，立即接入 frontidle 待机；不需要等原动作结束。松手继续已经显示的待机时间点，再执行原有点击反馈与触摸回应。快速松手、重新按住也不能恢复被打断的旧动作。真正拖动后仍使用原起飞、惯性和落地规则；抓住旧飞行后先回待机，旧飞行证据失效，不能凭旧手势补落地。

参考当前 DeepSeek sprite.js 的缓存复用、当前循环去重和回调归属处理，本轮做了以下修改：

- 非待机动作提交有效帧后，用空闲的后台视频准备待机画面；只有原有两个视频，不增加第三个解码器，也不在按下时争抢尚未提交的缓冲。
- 返回待机时，已解码的后台待机可直接提交，不重新设置地址或 load；已在待机时直接接管归属，不重置时间点。视频真正换流时仍等待有效解码画面。
- 保留 0.8.13 的单一持续透明画布，所有呈现都只替换一张有效人物画面，不把两个姿态做透明度叠加。缺帧继续显示上一张有效画面。
- 原生输入先发送，切换动作的旧回调失效；待机首帧未准备好时保留当前画面，完成解码后才替换。没有通过清空人物或继续播完旧动作来绕过交互。

主要源码位于 product-electron/app 下的 video-player.js、desktop-renderer.js、performance-director.cjs。版本标识和隔离 smoke 同步更新；frame-guard.js 的单画面实现保持。
