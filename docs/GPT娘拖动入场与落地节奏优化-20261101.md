# GPT娘拖动入场与落地节奏优化

2026-11-01按用户反馈完成并安装 `0.7.3-drag-responsive.1`。本轮保留落地动画，针对飞行出现太晚和提前松手接点的停顿感优化。

## 定位与最终行为

原flutter前约两秒主要仍为站立准备，旧拖动从0帧开始；前轮判断只核对已呈现同轮飞行片，首帧像站立仍会被算作已飞行。真实冷加载两张关键图集各约200–250ms，原180ms淡化又在接点保留一张静止旧姿态，放大了延迟感。单独CPU混图方法在本机测量约2.3–6.3ms，不能把所有卡顿都归因于混图算法或声称有唯一根因。

最终只更新 `runtime/dragon-animation/motion-runtime.ps1`：

- 按住实际拖动时，从原片66帧抬脚段进入，以1.5倍速度播放后续飞行；长拖仍保持179末帧。菜单手动点播仍从0帧原速，原片与图集未剪改。
- 首次正常待机呈现后，在后台预热flutter入场页1、draglanding首页0，并在原六页缓存内保护这两页。其他页按LRU淘汰，解码请求上限仍为2；没有扩大总页数，也没混入此前GC候选。
- 仅拖动/松手接点淡化缩至80ms，其余场景仍为180ms。
- 正常提前松手时，若飞行刚开始或尚在冷加载，短暂维持飞行，直到本轮起飞帧的呈现时钟达到120ms，再接落地。这个时钟以帧赋入控件为起点，不代表用户显示器逐帧采集证明看到了精确120ms。
- 400ms等待上限用于故障退路；若届时仍未得到足够起飞画面，回安全待机，避免凭空落地或一直卡住。常态短拖保留落地，不是将落地删掉。
- 落地仍从0帧开始，完整180帧、原30fps。异常停止/甩出不补地面落地，新菜单/触摸优先，重新抓起可立即打断。

两张预热页在低缓存占用的待机阶段额外占用约72MiB像素，优先占据六页中的两页，可能使其他不常用动作更早被淘汰。六页总上限保持不等于空闲内存占用完全不变。
