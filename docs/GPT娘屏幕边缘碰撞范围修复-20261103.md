# GPT娘0.8.7：屏幕边缘碰撞范围修复

基线为0.8.6-electron。用户反映：与DeepSeek相比，GPT娘尚未碰到屏幕两边就折返。

## 原因

物理速度、重力和反弹系数使用同一份共享核心，但传入的边界不同。DeepSeek的 `sideAllow` 会扣除身体两侧留白；GPT娘的 `motionBounds` 则让整块384×384方形窗口留在工作区内，透明区也提前触墙。

读取当前已安装透明视频的阈值10命中蒙版可复现：413像素窗口下，正面待机左右留白约74—100像素，飞行动作左右约73—94像素。这些原先都会成为提前反弹的空隙。真实蒙版核查覆盖待机、飞行、落地共540帧，见本轮 `real-mask-verification.json`。

## 改动

物理碰撞按当前实际呈现帧的透明轮廓计算左右和顶部。每帧轮廓结果绑定在经过SHA校验的蒙版缓存上，逐物理帧复用，缓存释放后可回收。全身、半身和自选静态图片使用各自轮廓；按压回弹的竖向缩放也纳入顶部计算。透明窗口部分可到屏幕外，人物轮廓到边缘才反弹。

全身落地仍以既有360/384脚底基线定位，避免飞行抬脚造成地面上下移动；半身按自身图片底部定位。重力、甩出门槛、反弹系数、起飞和落地素材、语音、个人大小及跟随模式没有调整。

显示器选择和接缝判断使用人物范围/中心。相接的屏幕继续可穿过；不相接的空隙、较短邻屏的外露部分仍有边界，工作区保留任务栏空间。多屏布局验证为几何测试，实际多屏/DPI观感仍需用户验收。

同时修正重启定位与调整大小的夹取：按人物范围留在工作区，不再把刚刚贴边的人物按整块画布向内拉回。缩放仍保持脚底锚点。启动预取一段既有正面蒙版作为稳定定位参考，仍受原有缓存预算限制。
