# 透明候选甩出后动作归属修正

2026-11-02。用户明确反馈发生在已经松手甩出之后：途中人物突然重播或换成飞行姿态。只修隔离候选，不修改正式WPF或DeepSeek安装。

## 原因与修正

09试用日志记录一次真实throw：起飞请求在松手前发出，松手后没有第二条起飞请求。候选继续完整起飞准备时间线，因此窗口已在惯性运动、人物稍后才进入离地段。不能将这份日志说成已经证实“中途重播”；它证明了延后的姿态变化路径。旧 `Motion.end` 还存在松手时补发takeoff的备用分支。

- `integrations/gpt-niang/playback-lab/desktop-motion.cjs`：末次松手样本照常参与速度与位置计算，但不启动新的起飞表演；真正甩出只发送coast。原速度估计、重力、反弹与自然停稳后一次落地保持。
- `desktop-input.cjs`：真实pointerup及看门狗补松手都不以末次位置样本启动起飞。
- `desktop-release.js` / `desktop-renderer.js`：取消尚未显示的待加载起飞。若实际呈现仍在flutter第0至65帧，锁住当时画面，不在惯性运动中继续推进到离地；实际已呈现第66帧及以后则保留当前片段，不从头加载或seek。
- `frame-guard.js` / `video-player.js`：锁画面时按当前透明保留层、视频层顺序及实际opacity合成快照，避免把淡入中的视频突然提升为完整画面。暂停视频、取消旧回调；后续明确动作仍可正常接管。新的抓取不会自动解除该锁定并续播旧起飞。
- `desktop-main.cjs`：记录释放模式和实际帧，方便进一步诊断。单一可见互斥量、透明交接保护、事件直连跟随和固定尺寸保留。

这是一项明确的表现取舍：准备尚未完成的短甩保留松手姿态，不再在半空补完起飞。该静止姿态与随后落地的接点是否自然尚未验收，不能据逻辑修正宣称整个动作链已达最终质量。
