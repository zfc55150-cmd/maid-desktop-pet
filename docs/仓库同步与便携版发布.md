# 仓库同步与便携版发布

源码和下载包分两步交付。推送 `main` 只更新 GitHub 源码。桌宠检查的是 [GitHub 最新正式 Release](https://github.com/zfc55150-cmd/maid-desktop-pet/releases/latest)，所以打标签、推送提交、保存草稿都不会让用户收到提醒。

## 同步和推送源码

在仓库根目录用 PowerShell 运行：

```powershell
node scripts/repo-sync.cjs
node scripts/repo-sync.cjs --fetch
```

第一条离线查看分支差异和工作区状态；第二条获取最新的 `origin/main` 后再比较。两条都不会合并、暂存或推送。工作区干净且只落后时，可用 `git merge --ff-only origin/main` 快进；历史分叉时，先用 `git log --left-right --oneline HEAD...origin/main` 看双方提交，再从 `origin/main` 开独立分支挑选仍需要的改动。保留当前工作区，避免把已被远端发布提交收纳的内容再提交一次。

只暂存本次修改的明确路径，用 `git diff --cached` 复核。提交后，如果要直接推送 `main`，先运行：

```powershell
node scripts/repo-sync.cjs --pre-push
```

它刷新 `origin/main`，在分叉、落后、工作区未清理、待上传历史含已知敏感文件名或源码验证失败时停止。检查通过后再显式运行 `git push origin HEAD:main`。ZIP、原始素材、个人状态、凭据和日志留在 Git 之外；需要评审的改动可走独立分支和 PR。

## 准备和核对下载包

对外使用单独的发布号 `vX.Y.Z`。GPT 娘另有本体版本（例如 `0.8.22-electron`）；对外比较使用 ZIP 内嵌的 `releaseTag`，并核对 `package-manifest.json`、`product.json`、启动引导最终写出的版本与 Release tag 一致。GPT 娘用包内 `node\node.exe app\package-doctor.cjs "."` 验证。

DeepSeek 娘可从已核对、未运行过的便携版 ZIP 构建带提醒的候选包。这个入口只打包提醒相关文件；如果还有其他 DeepSeek 功能改动，应先做好包含这些改动的干净基包。

```powershell
python scripts/build-deepseek-portable-reminder.py --base <旧版ZIP路径> --base-sha256 <已核对的SHA256> --tag vX.Y.Z --out <新候选目录>
```

脚本校验基包哈希、写入新发布号、复验 ZIP 内容，并输出候选包的 SHA-256；同名候选不会被覆盖。用干净目录试解压，验证启动和停止。两款 ZIP 都应附到同一个 Release，再按确切附件名生成 `SHA256SUMS.txt`（`Get-FileHash -Algorithm SHA256`）。

源码提交确认后，为对应提交打一个新的 tag（`git tag -a vX.Y.Z <已核对的提交SHA> -m "Release vX.Y.Z"`），只推送这个 tag（`git push origin refs/tags/vX.Y.Z`）。在 GitHub 创建 **草稿**，选这个 tag，上传两款 ZIP 和校验文件。逐一核对附件名称、大小、SHA-256 和版本说明，确认齐全后再发布为最新正式版。若用 GitHub CLI，可用 `gh release create <tag> --verify-tag --draft <附件路径> ...`；最终发布前在 GitHub 草稿页面检查。发布后再从公开页面确认下载入口、README 与附件相符。

## 下载用户会看到什么

- GPT 娘 v1.0.1 已带提醒：默认开启，每个新版本提示一次；「设置」里可检查更新并前往下载。
- DeepSeek 娘 v1.0.1 没有检查代码。用户第一次需要手动换成带提醒的便携包；之后，仅在公开正式版有新版 DeepSeek 娘 ZIP 时才显示提醒，点击「前往下载」打开对应发布页。两款都由用户自己下载安装。
