# 仓库同步与便携版发布

源码和下载包分两步交付。桌宠检查 [GitHub 正式 Release](https://github.com/zfc55150-cmd/maid-desktop-pet/releases)。发布带有对应宠物有效附件的 Release 后，客户端才能发现新版本。

## 同步和推送源码

在仓库根目录用 PowerShell 运行：

```powershell
node scripts/repo-sync.cjs
node scripts/repo-sync.cjs --fetch
```

第一条离线查看分支差异和工作区状态；第二条获取最新的 `origin/main` 后再比较。两条都不会合并、暂存或推送。工作区干净且只落后时，可用 `git merge --ff-only origin/main` 快进；历史分叉时，先用 `git log --left-right --oneline HEAD...origin/main` 看双方提交，再从 `origin/main` 开独立分支挑选仍需要的改动。保留当前工作区，避免把已被远端发布提交收纳的内容再提交一次。

只暂存本次修改的明确路径，用 `git diff --cached` 复核。提交后，如果要直接推送 `main`，先运行：

```powershell
node scripts/repo-sync.cjs --pre-push
```

它刷新 `origin/main`，在分叉、落后、工作区未清理、待上传历史含敏感文件名或内容、源码验证失败时停止。内容扫描覆盖目标树和每个待上传提交新增或改动的文本，命中时只报数量。可先用 `node scripts/repo-sync.cjs --scan-worktree` 检查未提交的源码。检查通过后再显式运行 `git push origin HEAD:main`。ZIP、原始素材、个人状态、凭据和日志留在 Git 之外。需要评审的改动可走独立分支和 PR。

## 准备和核对下载包

| 字段 | 来源 | 用途 |
|---|---|---|
| 发布标签 `vX.Y.Z` | 发版提交上唯一的正式 Git tag | 双宠共用，更新提醒按此比较 |
| GPT 本体版本 | product 的 `package.json` 与动作目录 revision 一致 | 附件 `GPTNiang-v<本体>-win-x64.zip`，反馈问题时连同发布标签提供 |
| DeepSeek 本体版本 | 项目 `package.json` 与 `deployment.json` 一致 | 附件 `DeepSeekActionPet-<发布标签>-win-x64.zip`，本体另记入发布说明 |
| 本地候选 | `candidate-<用途>`，新建工作目录保存 | 本地验收和传递技术结果，候选编号与正式标签独立 |

GPT 正式构建使用 `prepare-release.cjs <stage> --formal`，从干净工作树的 HEAD 读取唯一正式标签。脚本同步写入包内 `package.json`、`product.json` 和 `package-manifest.json`，doctor 检查一致性并输出两种版本。已安装本地版本沿用其发布比较基线。DeepSeek 正式发布构建现已接入 `scripts/build-deepseek-portable-release.py`（支持 `--formal` / `--release-name` 标签一致性校验与 `--force` 覆盖），同步向包内写入 `release-tag.json`（含 `tag` 与 `maintenanceVersion`）。

DeepSeek 娘可从已核对、未运行过的便携版 ZIP 构建带提醒的正式或候选包。构建入口会先运行 `sync-shared.cjs` 与 `verify.cjs` 校验，再打包维护清单中的运行时与提醒文件；如果还有其他 DeepSeek 功能改动，应先做好包含这些改动的干净基包。

```powershell
python scripts/build-deepseek-portable-release.py --base <旧版ZIP路径> --base-sha256 <已核对的SHA256> --tag vX.Y.Z --out <输出目录> --release-name
```

脚本校验基包哈希、过滤 `RESTRICTED_FOLD` 受限文件、写入 `release-tag.json` 并复验 ZIP（断言 0 个受限文件、单次启动提醒接线），输出 SHA-256。首启验证候选由 `scripts/build-deepseek-portable-fix.py` 构建，含包内配置初始化、独立停止及系统字体。正式发布前，用下列命令生成并审阅两包的逐文件许可清单。任何待核实条目或禁止再分发条目都会返回非零。

```powershell
python scripts/check-release-assets.py <GPT ZIP> <DeepSeek ZIP> --report <许可核对报告.json>
```

同一 Release 上传两款 ZIP，并使用 `scripts/write-sha256sums.py`（纯 ASCII 无 UTF-8 BOM）按确切附件名生成 `SHA256SUMS.txt`：

```powershell
python scripts/write-sha256sums.py --output <输出目录>/SHA256SUMS.txt --base-dir <输出目录> <GPT ZIP> <DeepSeek ZIP>
```

使用干净目录分别验证启动和停止。自 `v1.0.6` 起公开双宠便携包均已内置轻量化更新提醒，端到端提醒测试可直接基于公开 `v1.0.6` 双宠实包检查是否仅弹出一次新版本提醒。

源码提交确认后，每次准备新版本前先运行 `node scripts/build-manifest.cjs v<上一正式版>` 将 `deployment.json` 的 `previousRef` 与 56 条 `previousSha256` 刷新为直接前驱正式版本（`node scripts/verify.cjs` 与 CI 会自动按 `previousRef` 校验哈希链，并保证 `install.ps1` / `deployment-safety.cjs` 升级路径自洽）。注意：DeepSeek 便携包由 `build-deepseek-portable-release.py` 构建时会在 `main.js` 插入一行 `DSH_HOME` 用户目录重定向并生成 `release-tag.json`（GPT 便携包则通过 `product.json`/`package.json` 的 `releaseTag` 识别版本，不含 `release-tag.json`），`node scripts/verify.cjs --installed-root <便携解压目录>` 已兼容该已知单行注入、4 项 `"restricted": true` 素材过滤及 `release-tag.json` 生成文件校验。

为对应提交打一个新的 tag（`git tag -a vX.Y.Z <已核对的提交SHA> -m "Release vX.Y.Z"`），只推送这个 tag（`git push origin refs/tags/vX.Y.Z`）。在 GitHub 创建 **草稿**，选这个 tag，上传两款 ZIP 和校验文件。逐一核对附件名称、大小、SHA-256 和版本说明，确认齐全后再发布为最新正式版。若用 GitHub CLI，可用 `gh release create <tag> --verify-tag --draft <附件路径> ...`；最终发布前在 GitHub 草稿页面检查。正式发布上线后，**必须**运行如下发布资产闭环校验命令（支持 `GITHUB_TOKEN` / `GH_TOKEN` 环境变量以提升 API 限额；旧版分卷目录则用 `--parts`）：

```powershell
python scripts/verify-github-release.py --portable-dir <输出目录> --tag vX.Y.Z
```

该命令会校验本地 `SHA256SUMS.txt` 纯 ASCII 无 BOM、本地 ZIP 哈希一致，并比对远端 GitHub Release 的公开状态与全部上传附件的 size / sha256 digest，结果写入 `work/github-release-validation.json`。发布后再从公开页面确认下载入口、README 版本总结句与当轮审计状态数相符。

## 下载用户会看到什么

- 自 `v1.0.6` 起，双宠便携包均已自带轻量更新提醒（支持中/日双语）。「设置」里可检查更新并前往下载，DeepSeek 娘亦在主进程启动时按发布基线对比提醒。
- 本轮源码筛查最近一页 10 个 Release，取其中包含本宠有效 ZIP 的最高正式版本。正常 24 小时检查一次，查无本宠附件时一小时后再查，GitHub 限流时按退避时间执行。
