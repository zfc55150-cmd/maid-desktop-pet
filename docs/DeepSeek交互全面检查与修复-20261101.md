## 经核验并统一修复的问题

| 问题链 | 修复后的行为 |
| --- | --- |
| 新抓取开始时旧准备请求仍可提交；外部工作/碎碎念动画在抓取或飞行时抢入 | 抓取取消旧代次；蓝鲸拖拽拥有自己的动画请求，外部状态/文字可更新，画面不抢占，不排队补播旧事件 |
| 晚到碰撞通知在抓住/菜单期间又启动物理 | 明确用户输入优先，过期碰撞不启动飞行 |
| 取消/失焦/丢捕获仍按残余轨迹估初速；其他pointer松手结束当前手势 | 只有正常pointerup可估抛掷初速；取消安全放下，同一pointer收尾 |
| justDragged依赖100ms计时：迟到click漏出、下一次真实点击被吞 | 按手势消费一次拖后click，新按下立即恢复正常点击；右键作为新明确手势可独立打开菜单 |
| 旧点击的pendingSquash附着到后来拖动/事件；重复准备挤压旧画面 | 挤压随具体请求保存，仅对实际提交的目标帧生效；取消丢弃旧反馈 |
| 缓存后台视频从上次中途时间继续，进入动作像突然跳到中段 | 新动作缓存重播从0开始；已在前台的同一个循环仍不无故重播 |
| 移动计划尚未呈帧就改anim/once/朝向，或双向都无路仍翻身 | 计划与可见状态分开，首帧提交后同步朝向并开始位移；失败计划不改可见朝向 |
| 菜单打开后旧动作结束进入随机漫游；延迟click可干扰菜单 | 菜单/聊天/形态切换期间不启动随机漫游；菜单期间忽略宠物的迟到click |
| loadeddata后提前清超时；play失败也提交；销毁后旧回调可复活 | 超时覆盖首个实际视频帧，拒绝失败提交并受控回到可用待机；清监听、帧回调和计时器，销毁后不提交 |
| 中断回弹只停rAF、不恢复transform，切形态后可能保持压扁比例 | 保存并恢复目标元素比例和transform-origin，新的反馈开始前清旧反馈 |

正常超过拖拽阈值播放抓取反馈是原设计，未禁掉。慢速松手仍停原处，真实快速甩出仍保留原重力、反弹、摩擦和边界参数。其他文件宠物不被套用蓝鲸的输入期动画门控，GPT正式WPF完全未改。
