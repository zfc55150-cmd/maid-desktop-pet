## 要检查的范围

1. **全库逐段看完整原速。** 从头到尾看每一段，并逐帧解码扫一遍。先按桌宠日常显示大小看整体节奏和表演，再对可疑区间慢放、逐帧确认。用浅色和深色背景检查透明边缘、绿边、残影、薄雾、亮度跳变、局部消失、火光和道具合成。看角、翼、尾、头发、手、脚和道具是否突然换形、穿插或漂移。留意脚底滑动、重心不稳、比例忽变、拖尾和不合理停顿。静止、蓄力和设计中的短暂停顿先按动作语义判断。
2. **沿真实触发路线查衔接。** 建一张表，标明每段由手动、自动待机、任务、点击、拖拽、过渡中的哪些入口触发。检查是否有已安装但无可达入口、菜单错绑、动作被频繁打断或同一动作反复抢占。覆盖三种站姿的循环接缝和换姿、任务进入和退出、展扇和提灯的收势、正面悬浮降落、拖拽起飞、长按悬停、松手落地、甩出停稳和播放中按压回待机。过渡片应放在所属动作链里判断。自动轮换用隔离环境的可复现任务和时间场景触发，记录实际出场，勿从配置推断都已播放。
3. **三条新片做九条完整路线。** 分别从正面、侧身、长裙站姿点播每条。记录起始站姿 → 实际转向 → 完整动作 → 正面待机，检查首尾各十帧及其前后。特别看透明混合是否出现双轮廓、发丝或手脚先淡掉再出现、人物颜色突然变浅、脚底横移或末尾顿一下。另查《龙息凝星》的聚星和收星、《揽镜自赏》的镜子出现和收回、《执卷巧接》的卷轴展开、滑落、接住是否连贯。动作中段也要查，尤其是道具突然换形、跳位或动作因果看不懂。
4. **区分原片节奏与播放器掉帧。** 对异常区间对照原母版（如存在）、安装 WebM 的解码帧序列、播放路径和实际呈现时间。检查帧时间戳、连续重复或近重复帧、运动中断、异常大的帧间隔；在真实 Electron 播放路径用可获取的媒体时间、帧回调、呈现计数、掉帧计数或同类证据复核。对照正常和异常的帧间隔，报告触发条件与复现次数。标称 30 fps 不能证明播放流畅，录制工具或探针自身采样遗漏也不能直接算桌宠掉帧。有疑点时用同一路线重跑，区分素材内部、片间衔接、调度抢占、解码或窗口合成。定位不了就标「来源未确认」。

## 验收方式和交付

- 先用只读清单、完整视频和隔离 Electron 验证。测试用独立目录、假数据和本地播放，避免影响正在使用的正式桌宠。未经我明确同意，不抓取真实桌面、不启用会留下黄色捕获框的工具。若离屏和日志无法判断真实显示器上的抖动、掉帧或混合 DPI 问题，写清具体待验场景和所需操作。
- 交一份 Markdown 报告，先列最影响观感的问题和优先顺序，再附**全库逐段覆盖表**和**动作链覆盖表**。逐段表至少有动作名、ID、触发入口、原速检查情况、逐帧检查情况、观感结论与证据。动作链表列起始姿态、触发方式、实际播过的片段、结束姿态和结论。明确列出哪些只做了静态或离屏检查、哪些没测，以及具体原因。
- 每个问题给出**动作名和 ID、从哪里触发、时间码和帧号范围、肉眼现象、复现次数、原因判断和置信度**。尽量附问题前后各 1–2 秒的原速短片、关键帧对照或帧时间日志，写清帧号从 0 还是从 1 开始。单帧截图不能替代对卡顿或衔接的连续证据。现有自动测试通过也不能替代观感验收。
- 给每项明确的处理建议。需要辅助素材时，列出最小补片范围、前后应取的参考帧、姿态、道具状态、脚底落点、预计时长、接入路线和验收标准。若现有母版中段也有问题，把它与片间衔接分别评价。以观感决定修整或生成，不因 API 成本把可见缺陷标成通过。
