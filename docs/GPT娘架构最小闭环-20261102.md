# GPT娘 Electron 最小闭环：决策与执行记录

本轮授权方向是 Electron/Chromium 透明视频、局部替换。正式 WPF、DeepSeek 共享代码、个人数据、母版和回退材料受保护。本文件在实现前先固定责任与转移规则，实际验证结果另行追加。最终画面与交互由用户验收。

## 责任与唯一所有者

| 层 | 所有者 | 输入 / 输出 | 禁止承担 |
| --- | --- | --- | --- |
| 产品 | 当前 WPF 服务与设置；候选暂用只读基线 | 未来通过明确适配器输入任务、额度、形态和设置 | 候选不写正式状态，不启动第二个产品观察器 |
| 输入 / 物理 | InputDriver / Motion，主进程 | 屏幕坐标、手势 → grab / qualified / release / rested / cancel；位置与速度 | 不认识视频名、帧号、落地片；视频不得决定物理 |
| 表演 | PerformanceDirector，主进程 | 物理语义、手动命令、可呈现媒体证据 → 唯一 requestId 的表演计划 | 不移动窗口、不读取 DOM、不解码 |
| 媒体 | Player 与 renderer 适配器 | 不可变计划/归属 → 解码帧、完全不透明且非 seek 的媒体帧、结束、错误 | 不决定物理停稳或起飞资格；回调不等于屏幕显示 |
| 几何 | desktop-geometry 的单一规格 | 384 画布、335 待机参考高、360 脚底 → 固定窗口、坐标和命中映射 | 不从窗口读回宽高反向放大，不裁掉离身道具 |
| 生命周期 | review-session / lease / restore-widget | 安装基线、空闲检查、单显示权 → 手动退出与恢复 | 不静默超时切版，不强杀任务，不写个人设置 |

最小拆分是新增表演调度器和素材语义目录，复用已有输入、物理、播放器、显示权模块，不引入框架或服务。flutter 的离地帧与分段速率只属于素材目录。物理时钟独立于表演切换；恢复待机不停止惯性。

## 状态与中断规则（实现前合同）

| 事件 / 场景 | 物理 | 表演与媒体 | 失效规则 |
| --- | --- | --- | --- |
| 慢拖放下 | drag → idle，停在放下处 | 保持正常动态反馈，释放恢复待机；无离地证据不落地 | 撤销未提交起飞 |
| 快甩，未离地 | drag → flight → idle | 松手立即取消待切片，随后淡回动态待机；不补起飞、不落地 | release 锁定本轮离地资格为 false |
| 起飞准备中松手 | 与速度判定相同 | 准备不继续推进为离地，恢复动态待机 | 迟到起飞命令/帧不能改变资格 |
| 实际呈现离地后松手 | 惯性独立推进；无惯性则立即停稳 | 松手恢复动态待机，停稳后一次落地与待机返回 | 仅同一 requestId、同次手势、完全不透明媒体帧可作证 |
| 惯性中抓回 | flight → drag，清空旧速度 | 新抓取取得表演权，取消旧落地资格 | 旧物理步/媒体返回均失效 |
| 碰撞停稳 | flight → idle | 有 release 时锁定证据才落地，否则维持待机 | 消费一次资格；重复 rested 无效 |
| 加载期间抓取 | 任意 → drag | 撤销旧加载与返回，恢复动态待机反馈 | 旧请求即使首帧迟到也不能提交 |
| 菜单打断 | 取消拖动与惯性 | 解除 renderer 按住状态；待机，不补落地 | epoch 递增、捕获与旧请求失效 |
| 指针丢失 / 失焦 | 保守取消，不制造甩出 | 恢复待机 | 不使用旧光标样本推断正常松手 |
| 旧异步回调迟到 | 不变 | 丢弃，与当前 requestId/手势不符即无效 | 视频槽复用不复活旧回调 |
| 媒体错误 | 物理继续独立运行 | 当前计划失败后仅一次待机恢复；恢复再失败保留有效画面并报错 | 不无限重试，不拿旧帧证明新动作 |

优先级：退出/取消 > 新抓取/菜单 > 同次释放与自然停稳 > 手动表演 > 空闲。手动表演在拖动/惯性期间拒绝，不排队突袭。动作结束由当前媒体计划处理返回，旧计划不能接管。抓取中若起飞片自然结束，回动态待机而非长期静止。

松手的瞬间保帧仅用于撤销加载并跨越 IPC 交接，不能持续整个惯性。缺少专用中断回姿素材时采用现有待机与短淡化；已离地后的待机→落地接点属于已知视觉待验收项，不声称连续姿态已获认可。

## 质量收益与仍未验证项目

### 五分钟切换与资源复测

`-01/soak-smoke.json` 与 `-02/soak-smoke.json` 各实际运行约301.4秒：30秒待机、150次间隔800ms的切换/取消、五组原速表演、80秒待机恢复。两轮均无运行错误、video元素保持2个；最终版追踪335项、帧样本6736项，缓冲有上限。没有强制GC。该测试是压力场景，不把切换次数视为角色品质。

第一版校验通过 `readFileSync` 整文件读入225MB级运行时以及图集，造成不必要的大临时缓冲；第二版改为64KiB分块哈希，SHA验证语义相同。两轮使用相同视频与速度，结果如下（4个候选进程，Electron报告的privateBytes合计）：

| 指标 | 第一版 | 当前第二版 |
| --- | ---: | ---: |

### 产品接回的实际所有者

本轮核对了当前安装源码：`widget.ps1` 的 Save-Settings 经 `runtime/settings-store.ps1` 按Revision摘要保护写入settings；`runtime/pet-forms.ps1` 的 Write-WidgetPetForm 经同一保护保存pet-form。额度由 `runtime/watch.mjs` 的单worker锁与刷新队列拥有，产出status.json；该worker目前绑定WPF父PID，父进程退出/stop请求会结束。任务观察由 `runtime/dragon-animation/dragon-animation.ps1` 启动activity-watch.mjs，服从task-observers-paused.flag。WPF还拥有presence与菜单/文字展示。

因此不能仅在Electron里再启动一份观察器，或以“保留文件”等同“功能已接回”。第四阶段应先让一个产品适配器持有产品状态/worker生命周期：任务/额度快照只作为输入交给表演调度，设置与形态修改经原有Revision保护单写入者，UI操作带来源/修订号，不让renderer直接读写个人目录。WPF全身播放器与Electron不得同时消费输入或拥有显示权；原半身素材/音效规则保留，切形态由同一显示与设置所有者完成。如何脱离当前WPF父PID而继续服务，必须在隔离产品适配验证中落地，本轮没有修改正式worker或启动双份查询。

已确认的收益是状态责任可追踪，旧起飞/返回/离地证明不能跨手势复活，正常释放不再长期冻姿，几何保持固定；这些有行为与真实媒体组合证据。没有证据证明新播放器画质已优于正式WPF或综合体验已达到DeepSeek。

同源同人物物理高度、DPI、背景与原速的真实桌面A/B尚未完成。窗口344×344由335/384待机参考高与300px目标计算，**不是屏幕实测人物物理高度认证**。请求到首个完全不透明媒体回调的内部耗时可以记录，但不等于输入到首次屏幕变化。未取得显示器刷新/屏幕真实变化轨迹，不认证“满60帧”。

仍未验证：真实拖动/碰撞连续移动与输入延迟、冷文件缓存加载、脸/发丝/衣纹/尾巴动态保真、淡化叠影、长拖动后恢复自然度、已离地后动态待机→落地的姿态接点、多DPI/多屏跨越、真实系统捕获及不抢焦点、两宠碰撞、60分钟资源收敛及GPU实际利用率。focusable=true、进程内强制DSF=1、关闭硬件加速均为候选限制；不能默认可正式沿用或透明VP9硬解。
