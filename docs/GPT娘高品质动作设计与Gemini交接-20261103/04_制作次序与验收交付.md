# 制作次序与验收交付

## 执行边界

本包是用户交给 Gemini 的视频制作任务。主助手已经完成现有素材核对、设计和参考整理；**视频API未调用，六条新动作尚未生成，当前桌宠与个人设置未改。**

制作先后建议 P01→P02→P03→P05→P04→P06：先确立人物表演和受控物体，再解决翼尾运动、机关、材质、倒影与液体。默认先提交P01一个完整候选；其余按用户在接手会话的授权推进。不是每个本地可逆后期步骤都要重复确认，也不默认允许无限批量抽卡。

优先复用本机已授权的视频入口、模型与工具；当前真实配置和额度以接手环境为准。不要读取、输出、复制或把密钥写到提示词/命令行/交付包。不要把非视频Key回退用到视频接口。若使用本机qwen-helper，先读 `%USERPROFILE%\Documents\Codex\2026-10-20\dui\qwen-helper\AGENT_USAGE.md`，通过程序读取受保护的视频配置；本包不提供解密步骤。

质量目标不因单次价格降低，但不授权充值、购买套餐、抬高本地预算、切换服务商或扩大自动任务。接口报错/预算不足，明确报告影响，不盲目重试；继续不依赖接口的分镜、预演、抠像或精修。单个大模型下载超过10GB仍需先说明模型、用途、大小和路径并等用户确认。

不修改本项目应用代码，不改 `deployment.json`，不覆盖认可原片、正式资源和回退目录，不安装或重启GPT娘/DeepSeek。生成后交候选，由主助手处理技术接入、运行回归和用户视觉验收。用户后续明确扩大授权时，以其新指示为准。

## 第一步：现场能力核查

记录实际提供方、模型ID、调用方式、最大时长/分辨率、原生帧率、首帧/尾帧/独立身份参考能力、续段能力、是否能关闭音频、透明支持和费用/预算状态。需要外部事实时查当前官方文档，不能凭旧报告猜模型能力。提示词的“14秒”“1440”不是接口参数。

如果模型只支持8秒而P01需要14秒：先给出分段与衔接方案，例如保持同镜头的6秒控纸＋8秒归叠收尾，明确中间约束帧与连续手位；或者用人物连续底片＋受控纸页动画。不能一边保留14秒导演稿，一边提交8秒并宣布完整。跨段不得靠显眼切镜掩盖动作缺失。

本轮不附具体服务URL、参数名或价格，避免失效文档误导。能力与账户核查不应向用户展示凭据。

## 第二步：提交前先做可以审的设计

1. 按主锚点锁住脸、比例、左右和服装，确定独立安全画布，不覆盖原图。
2. 为当前一条制作关键姿态与道具状态板，至少覆盖起势、主动作峰值、转折、收势；P02建议约12个运动关键姿态。静态姿态板不是视频完成证明。
3. 低成本预演只检验时长、剪影、身体运动和接触关系；允许几何体/线稿占位，不能拿它代替最终美术。
4. 主助手的导演稿优先。Gemini可提出更好的实现路径，但不得无声删掉尾巴接触、空中整圈转身、机关展开或金缮落笔等必达事件。
5. 拼接 `prompts/00_common_identity.txt` ＋当前一条英文提示词。只有确实支持独立参考的字段才发送结构图；主锚点作首帧时不要把三视图塞进去。原片、参考和首尾字段的真实用途留记录。

## 第三步：分开审四层

|审查层|检查对象|通过标准|
|---|---|---|
|设计实现|未抠原片，原速|每条主事件、必达接触、情绪转折发生；不是静姿加特效|
|美术连续|原片与精修片，必要时逐帧|脸、角、手、翼根、尾根、服装和道具结构不跳；支撑与遮挡连续|
|合成与透明|透明母版，在浅灰/近黑/饱和底原速|无明显绿边、漏抠、闪烁、白发变薄；反射、液体有可用透明层|
|实际呈现|约300px人物高度预览；之后由主助手在实际用户大小复核|无需文字解释可读主事件，表情峰值不一闪而过，重要接触看得清|

技术可解码、完整帧数、没有报错不能替代艺术通过。生成端自评“完美”不算用户认可。别只交慢放剪辑或最漂亮的几张静帧。

缺陷记录统一写作 `P01 v01｜00:05.200–00:05.700｜右手接纸处穿模｜原片即有/后期引入｜处理与剩余问题`。帧定位同时注明帧率或原片PTS，不能仅用转码后帧号。技术检查至少应完整解码且无解码错误、时间戳顺序有效、实际尺寸/帧率/时长可读取，并核对透明通道；是否流畅、掉帧或画面撕裂应在具体播放器和设备上单独测试，不给未知环境编造容忍阈值。

**整条返工条件：**明显换脸/比例改变；角色或尾翼增生；手与物体融合；主事件缺失；用切镜/闪白代替步骤；关键物体轨迹出框；显著口型；靠全身贴图旋转冒充P02；道具失去固定结构。轻微不足具体标注，可让用户判断，不用分数替用户做喜好决定。

## 每条必须交的文件

```text
P01_paper_command/v01/
  source_original.<真实源格式>    未抠未变速原片，保留原音轨状态记录
  prompt_final.txt                真正提交的完整提示词
  request_redacted.json           仅非敏感参数；无Key/凭据/签名下载URL
  generation_record.json          模型、时长、帧率、尺寸、时间、费用口径、任务ID
  reference_used.png              真正提交的首帧/参考；多参考逐项列用途
  first.png / key_peak.png / last.png
  master_alpha.mov 或 rgba/       高质量透明母版，若尚未完成明确标注
  preview_small.mp4               人物约300px高、原速、有说明的合成底预览
  review.md                      必达事件逐项结果、缺陷时码、用户反馈状态
  layers/                        有分层时交人物、道具、光效、遮挡与工程
  hashes.sha256                  相对路径和SHA-256
```

API源规格和母版规格分别记录，后期放大、插帧、分段、修脸、局部重绘都如实登记。无损母版/分层尚未完成时可以先交原片供看，但不能标“全部验收完成”。不为临时预览复制整套应用和全部旧素材。

## 最终回交给主助手的清单

- 当前制作了哪些编号，各有几版，用户明确认可的是哪一版。
- 原片、透明母版、工程与原速小图路径；逐文件哈希。
- 每条必达事件的结果和具体问题时码；技术通过与视觉认可分别列出。
- API实际源规格、模型、分层/续段/插帧/后期详情和费用口径；不含密钥或个人记录。
- 尚待完成的部分；不得把失败版本或只有脚本的任务说成已完成。

最后是否接入正式产品，由主助手在现有Electron维护入口完成。P02若只在视频内部移动，就按固定窗口表演接入；要让窗口真的沿路径飞行，需要另一项有轨迹同步的实现，不能靠视频设计文件宣称已完成。
