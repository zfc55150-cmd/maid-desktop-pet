# GPT娘按真实飞行判定落地

2026-11-02，用户要求普通拖放不能播放落地，应参考DeepSeek的飞行判定。已更新为 `0.7.3-physical-landing.1`。有效包 `work/gpt-physical-landing-20261102-03/`。

## 行为

普通拖动后放下立即退出拖动反馈，停在原处，不补播起飞或落地。此前“短拖松手后完成约一秒起飞再落地”的策略已撤销；播放过flutter不再代表发生了真实飞行。

只有原生控制器根据松手速度真正进入Flying状态，之后因物理运动自然停稳（rested）才允许落地。飞行过程中继续现有飞行反馈，不提前播放地面落地。落地保留180帧、1.2倍速，约5秒。

抓回、菜单、隐藏窗口、异常中断等interrupted路径不补播落地。一次物理飞行结束只触发一次；新菜单/触摸响应优先，隐藏或关闭动画期间的完成记录会被消费，不在恢复显示后突然补播。

## DeepSeek判定依据

已核对本项目实际维护/安装的 `app/electron-helper/shared-core.js`，其 `estimateReleaseVelocity` 与GPT原生 `PetNativeMotion.Estimate` 既有算法一致：最近150ms轨迹、停顿超过150ms失效、至少20ms跨度、段速度/加速度加权、3600软限速，最终速度达到500 DIP/s才起甩。不是单看拖动距离、持续时间或动画帧数。

本轮没有修改这些算法、阈值、重力或反弹参数。增加两个仅驻内存的原生序号：FlightSerial只在真正创建飞行时递增；CompletedFlightSerial仅在Flying状态以rested结束时记录。动画模块消费完成序号，能处理完整飞行发生在两次动画Tick之间的情况，并防止旧完成记录被再次使用。

三项受控更新：

- `runtime/native-motion.cs`：仅增加飞行/完成序号及标记。
- `runtime/dragon-animation/motion-selection.ps1`：物理Flying可保持飞行反馈；落地选择必须有同次原生完成记录。
- `runtime/dragon-animation/motion-runtime.ps1`：消费真实完成记录，撤销松手续播等待，普通释放返回待机；保留起飞时间线、预热、80ms接点及落地1.2倍速。

完整维护源在 `integrations/gpt-niang/drag-response/`，构建入口 `scripts/prepare-gpt-physical-landing.py`。基线为上一轮完整起飞包，构建前逐项核对现装文件，未覆盖并行的角色名、提示框、步行或DPI修复。

## 验证

`test-physical-landing.ps1` 共261项通过：

- 对原飞行动画0至179每一帧分别模拟普通松手，均不落地，也不继续强制飞行。
- 真正Flying时不提前落地；同次rested后从落地0帧开始，后续心跳不重复重启。
- 已被打断、没有飞行、旧完成序号、整个飞行跨过动画Tick、关闭动画期间完成、新菜单/触摸等边界。
- `flight-parity.cjs` 直接执行当前DeepSeek核心，生成66组假轨迹；GPT原生Estimate的是否起飞及速度与其相符，数值容差0.00001。
- 屏外真实C#控制器受控Launch/Pulse自然停稳时产生完成序号，Stop中断不会产生下一次完成记录。

`test-real-physical.ps1` 使用真实PNG图集、候选原生控制器及屏外WPF窗口，验证真实控制器的受控短飞行自然rested后播放落地0至179帧，再回frontidle；实测停稳至待机约5197ms。它使用程序化受控Launch来验证控制器与动画联动，不是用户真实鼠标甩出手感验收；实际松手阈值另由66组轨迹对照覆盖。测试未移动用户鼠标、未写个人设置、未调用付费API。

本轮没有重画/生成素材，没有调整人物大小、位置或DeepSeek的自启动。技术验证不作为实机观感通过。
