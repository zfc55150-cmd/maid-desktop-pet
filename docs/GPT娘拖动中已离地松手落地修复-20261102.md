# 拖动中已经离地，中途松手接落地

2026-11-02，用户澄清缺少落地发生在“拖着她时已经飞起来，中途松手”。上一版把飞行资格误限定为松手后的惯性飞行，因此漏掉了这一分支。本轮已更新为 `0.7.3-held-air-landing.1`。

## 判定

现在保留两个独立出口：

1. 拖动中曾按DeepSeek同一套速度算法达到起飞门槛，并且**本轮**flutter画面已呈现离地段（66帧及以后）：正常中途松手接完整落地，即使停住鼠标后松手、不产生惯性甩出，也能落地。
2. 松手后真正进入原生物理Flying：仍等同次物理飞行自然rested后落地，飞行途中不提前落地。

慢速挪动、尚未显示离地画面的短拖不触发落地。新菜单/抓回等异常中断、过期帧和上一轮拖动的飞行画面不能授权本轮落地。没有恢复“只要拖过就落地”，也没有恢复强制补播一秒起飞。

原生模块增加DragSerial和DragFlightEligible：BeginDrag创建新拖动并清空资格；ReadPointer中使用既有PetNativeMotion.Estimate，达到门槛后只在这轮拖动内保留资格。速度算法、150ms窗口、20ms最小跨度、500 DIP/s最终门槛与物理参数均未改。这里将同一算法用于**拖动中**的资格判断，而不只是松手瞬间，符合用户补充的手持飞行场景。

动画开始真正呈现时记录本轮DragSerial；松手时同时核对原生资格、当前拖动序号、实际呈现片段/帧序号和离地帧，避免把切换请求或旧画面误当成起飞。原生拖动反馈也改为速度达标后才启动flutter，慢拖不会自行播放到半空姿态。

起飞仍从0帧开始，准备段约1秒，后续1.25倍速；落地仍从0帧完整播放180帧，1.2倍速约5秒。预热、80ms接点和六页缓存上限保持。

## 验证

- `test-held-air.ps1`：544项通过，覆盖全部180个松手帧的速度达标/未达标组合、慢拖不进入飞行、尚未离地不落地、离地后松手完整落地、旧拖动序号、异常中断及不重复播放。
- `test-physical-landing.ps1 -Package <本轮包>`：既有261项再次通过，含66组DeepSeek轨迹速度对照、真实物理飞行的完成序号和打断规则。未退回“所有拖动都落地”。
- `test-real-held.ps1`：真实原生控制器、受控指针输入、真实PNG图集及屏外WPF窗口。先快速移动达到资格，继续按住至flutter第85帧，鼠标静止超过150ms后EndDrag。确认Flying=false、FlightSerial=0、StopReason=released，即**没有惯性甩出**，仍接落地0至179帧再回frontidle。末次实测约5215ms。
- 同一真实控制器再开启下一轮低速9像素/100ms拖动，Moved=true但资格为false，未播放flutter，松手不播落地。测试不移动用户鼠标、不写个人设置、不调用付费API。

上述是针对交互分支和播放接线的技术验证，未替用户判定画面观感通过。
